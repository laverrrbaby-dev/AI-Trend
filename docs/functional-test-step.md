# Step 3 功能测试与数据/UI一致性验收

本验收用于确认 Streamlit 页面在真实缓存数据模式下，数据读取、排行榜排序、筛选、日期切换、明细联动和图表数据保持一致。Step 3 不接入新数据源，也不调整评分模型。

## 代码层回归

```bash
python3 -m unittest discover tests
```

验收重点：

- `data/radar/YYYY-MM-DD.csv` 中 `主线得分`、`成交额(亿)`、`成交额排名`、`20日涨幅`、`60日涨幅`、`120日涨幅`、`5日份额变化`、`20日份额变化` 保持数值类型。
- `trend_radar.ui_data.load_snapshot()` 默认按 `排名` 升序读取，`排名` 表示主线得分排名。
- 完整排行榜按“成交额”排序时，展示顺序等于 CSV 中 `成交额(亿)` 数值倒序。
- 完整排行榜按“成交额排名”排序时，`成交额排名` 单调递增，`成交额(亿)` 单调递减；不要求真实数据排名从 1 开始。
- 表格展示层把 `排名` 显示为 `主线排名`，并保留排序相关列为数值类型，由 Streamlit `NumberColumn(format=...)` 负责格式化。

## 浏览器验收

启动本地页面：

```bash
streamlit run app.py --server.headless true --server.port 8501
```

使用 Codex Playwright skill 打开 `http://localhost:8501`，截图保存到 `output/playwright/functional-step/`。每次真实数据接入或 UI 表格逻辑调整后，至少执行以下场景：

- 初始页面显示“真实缓存”，不显示静默混用的 Mock 状态。
- “Top10观察池”按主线得分排名展示，完整排行榜排序控件切到“成交额”后 Top10 观察池不变。
- 完整排行榜切到“成交额”后，首屏 `成交额(亿)` 递减，同时表头显示 `主线排名` 而不是泛化的 `排名`。
- 切换数据日期后，数据状态、Top10、完整排行榜、主线变化提醒和 ETF 明细同步更新。
- 搜索 ETF 名称或代码后只显示匹配结果，清空搜索恢复全量。
- 趋势状态过滤后，榜单不出现未选状态。
- 选择完整榜单中的 ETF 后，ETF 明细标题、评分拆解、价格图、成交额图和份额图切换到同一代码。
